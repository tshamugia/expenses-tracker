## ჯვარედინი კონვენციები (ყველა ფაზაზე ვრცელდება)

### მონაცემები
- **ყველა თანხა** — `Decimal @db.Decimal(12, 2)`; Server Action-ში კლიენტისთვის `Number()` სერიალიზაცია (PRD D8, არსებული პატერნი).
- **მრავალვალუტა** — თითო ჩანაწერს თავისი `currency` (GEL/USD/EUR); დაჯამება მხოლოდ ჩვენების დონეზე, user default ვალუტაში, ოფიციალური კურსით (PRD D6). გამოიყენება არსებული `lib/services/currency.ts`.
- **ერთიანი ტრანზაქცია წყაროს ველით** — ყველა ფულადი მოძრაობა (`Transaction`) ატარებს `entrySource`-ს: `MANUAL | CLAUDE | IMPORT | BANK` (PRD R6, §7.10). ეს ფაზა 1-შივე იდება არქიტექტურაში, რომ ფაზა 5 (Claude) და ფაზა 6 (ბანკი) ლოგიკის შეცვლის გარეშე დაემატოს.

### არქიტექტურა
- არსებული სამფენიანი პატერნი უცვლელია: Client Components → Server Actions (`lib/actions/`) → Services/Prisma (`lib/services/`, `lib/db/`).
- **გამოთვლითი ლოგიკა (engine-ები) — მხოლოდ სუფთა ფუნქციები** `lib/services/` ან `lib/utils/`-ში, DB-ზე და auth-ზე დამოკიდებულების გარეშე. Server Action-ები მხოლოდ აწყობენ: auth → data fetch → engine → persist → revalidate. ეს ტესტირებადობის მთავარი პირობაა.
- ახალი გვერდები `app/(private)/`-ში, route protection — `auth.config.ts`-ის არსებული მექანიზმით.

### პროცესი (ფაზა 0 — ყველა PR-ზე ვრცელდება)
- PR არ იხსნება, სანამ ლოკალურად `npm run build` და `npm run test` მწვანე არ არის; მერჯი მხოლოდ მწვანე CI შემოწმებებით (branch protection).
- სქემის ცვლილება მხოლოდ მიგრაციით: `npm run db:migrate:dev` Supabase dev ბაზაზე → PR-ში SQL-ის review → მერჯის შემდეგ Railway pre-deploy `prisma migrate deploy` პროდაქშენზე. `prisma db push` სქემის ცვლილებისთვის აღარ გამოიყენება. დესტრუქციული SQL-ის წესები — [phase-0-workflow-ci.md](phase-0-workflow-ci.md) §5.

### ტესტირება (სავალდებულო)
- **წესი: არცერთი ფაზის ეტაპი არ ითვლება დასრულებულად ტესტების გარეშე.** დეტალური წესი — CLAUDE.md „Testing" სექციაში.
- Framework: **Vitest** (მინიმალური bootstrap ფაზა 0-შია; RTL-ით სრული სეტაპი — ფაზა 1 §8) + React Testing Library კომპონენტებისთვის.
- პრიორიტეტი: ფინანსური engine-ების (ამორტიზაცია, პროგნოზი, ჩანჩქერი, ვერდიქტი) 100%-თან მიახლოებული დაფარვა — ეს ის კოდია, სადაც შეცდომა ფულის არასწორ რიცხვს ნიშნავს.
- ყოველი ფაზის ფაილში არის „ტესტირება" სექცია კონკრეტული ტესტ-ქეისებით — ისინი ფაზის Definition of Done-ის ნაწილია.

### შეტყობინებები
- არხი — Email (Resend, არსებული `lib/services/email.ts`), მისამართი იცვლება პარამეტრებში (PRD §7.9).
- პრინციპი: „ცოტა, მაგრამ დროული" — შეტყობინება, რომელიც ქმედებას არ იწვევს, არ ემატება.
